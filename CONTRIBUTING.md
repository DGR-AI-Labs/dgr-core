# Contributing to dgr-core

Thank you for helping improve the public code. This project is experimental and does not currently make production-readiness or support guarantees.

## Public issue scope

Public issues are for:

- reproducible defects in the public code;
- build, installation, or public compatibility regressions; and
- errors or material ambiguities in public documentation.

Public issues are not the intake path for feature requests, roadmap or architecture proposals, pricing or go-to-market questions, customer matters, or other private planning. Maintainers track those matters separately and may close out-of-scope public issues without transferring internal context into GitHub.

Do not use a public issue or pull request for a suspected vulnerability, bypass, authorization or token weakness, replay, fail-closed behavior, secret exposure, or supply-chain risk. Follow [SECURITY.md](SECURITY.md) and submit the report privately through GitHub's Security tab.

## Before opening a public issue

Please:

1. Search existing public issues for a duplicate.
2. Reproduce the problem against an identified public version or commit.
3. Reduce it to the smallest complete example using public code and data.
4. Remove secrets, credentials, customer information, private repository names, and private planning information.
5. Use the applicable issue form and complete every required field.

## Pull requests

Keep changes focused, explain the observable problem and the proposed behavior, and include proportionate tests or validation evidence. A pull request requires maintainer review and does not imply acceptance of a roadmap or architectural direction.

Contributions must use only information that is safe to publish. Do not copy material from private systems into a commit, pull request, test fixture, log, screenshot, or discussion.

## Maintainer triage boundary

Public triage should discuss only the observable public-code or documentation problem. Internal priorities, customer context, security analysis, commercial plans, and unreleased architecture remain in their appropriate private systems.
